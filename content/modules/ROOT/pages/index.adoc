= Concert + AAP + Lightwell CVE Remediation Lab

== Lab Overview

Welcome to the Concert + AAP + Lightwell CVE Remediation Lab. In this hands-on workshop, you'll learn how to automate enterprise-scale CVE remediation using IBM Concert for vulnerability intelligence, Ansible Automation Platform for orchestration, and Red Hat Lightwell for trusted remediated packages.

== What You'll Learn

* How Concert identifies affected applications from enterprise-wide SBOM inventory
* How Concert assesses CVE impact and provides risk intelligence
* How Automation Orchestrator orchestrates remediation workflows
* How Lightwell provides verified, remediated packages
* How to validate successful remediation with complete audit trails

== Lab Scenario

A critical vulnerability (CVE-2026-52891) has been discovered in PyYAML - a Python package used across your application portfolio. Your security scanner has detected this vulnerability and needs immediate remediation.

**Without Concert**: You'd manually scan 500+ applications to find which ones are affected. This takes hours or days.

**With Concert**: Concert's pre-indexed SBOM inventory instantly identifies affected applications. Concert provides risk assessment and priority scoring. Automation Orchestrator executes the remediation automatically.

== Lab Environment

* **control**: Ansible Automation Platform with Automation Orchestrator and Event-Driven Ansible
* **rhel01**: Flask application server (vulnerable PyYAML 5.4.1 → remediated 6.0.2)
* **gitea**: Git repository + CI/CD pipeline
* **Concert**: IBM Concert instance (intelligence source, cloud-hosted)
* **Lightwell**: Red Hat Lightwell service (remediated packages)

== How to use this guide

The workshop sidebar tabs map directly to the infrastructure in `config/instances.yaml`:

[cols="1,2,2",options="header"]
|===
| Tab | Opens | Use it for

| **AAP**
| `https://control-{guid}.{domain}/`
| Automation Controller login (`admin` / `ansible123!`), jobs, EDA activations

| **Flask App**
| `https://app-{guid}.{domain}/`
| Vulnerable Flask API on `rhel01` (check `/version`)

| **Gitea**
| `https://gitea-{guid}.{domain}/`
| Repository, commits, and Actions pipeline (`labuser` / `ansible123!`)

| **Concert**
| Shared Concert UI
| Optional: browse Concert while workflows run

| **Terminal**
| SSH to `control`
| Run `curl` and other CLI commands against lab hosts
|===

When a step says "click the **Flask App** tab" or "open the **Terminal** tab", use the sidebar — do not invent hostnames or ports.

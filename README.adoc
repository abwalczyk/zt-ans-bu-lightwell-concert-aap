= Concert + AAP + Lightwell CVE Remediation Lab
:toc: auto

A hands-on workshop demonstrating AI-driven CVE remediation using IBM Concert for
vulnerability discovery and triage, Ansible Automation Platform for orchestration,
Red Hat Lightwell for remediated dependencies, and Gitea CI/CD for automated deployment.

== Workshop Modules

[cols="1,2,2"]
|===
| Module | Focus | Hands-on exercises

| *DISCOVER -- Concert CVE Detection*
| IBM Concert discovers CVE-2026-52891 (PyYAML deserialization) in a Flask application,
performs risk scoring and correlation, then triggers automated remediation via Concert Workflows.
| Configure Concert Automation Rule; review Concert Workflow that calls AAP API; observe CVE triage decision.

| *ORCHESTRATE -- AAP Remediation Workflow*
| Ansible Automation Platform receives the Concert payload, orchestrates Lightwell artifact
retrieval, updates application dependencies in Gitea, triggers CI/CD pipeline, and validates remediation.
| Execute AAP workflow template; observe Lightwell integration; monitor Gitea pipeline; review audit trail.

| *VALIDATE -- Remediation Verification*
| Verify that the vulnerable PyYAML 5.4.1 has been replaced with Lightwell-remediated 6.0.2,
application health is confirmed, and the deserialization attack is blocked.
| Run validation playbooks; test application endpoints; confirm CVE resolved; generate compliance report.
|===

== Architecture

[cols="1,2"]
|===
| Host | Role

| `control`     | AAP Controller 2.7+ (shared across labs)

== Setup

The automated setup provisions infrastructure and configures Concert Workflow, AAP job
templates, and the vulnerable Flask application. Students will execute the remediation
workflow and observe the CVE lifecycle.

=== What the setup creates

* Flask application with PyYAML 5.4.1 (vulnerable to CVE-2026-52891)
* Gitea server with application repository and CI/CD pipeline
* AAP job templates for remediation orchestration
* Concert Workflow configured to call AAP API
* Concert Automation Rule to trigger on CVE detection

=== What attendees execute

* Trigger Concert CVE detection (or observe auto-trigger)
* Monitor Concert Workflow execution
* Observe AAP remediation orchestration
* Watch Gitea CI/CD pipeline build and deploy
* Validate remediation success

== Prerequisites

* OpenShift Virtualization cluster with RHDP provisioner
* AAP 2.7+ controller (shared or per-lab)
* IBM Concert instance (shared, cloud-hosted)
* Red Hat Lightwell access
* RHEL 9.x base image

== Lab Flow

1. **Concert Discovery**: Concert ingests SBOM, detects CVE-2026-52891 in PyYAML 5.4.1
2. **Concert Triage**: CVSS 9.8 (Critical), remediation available (Lightwell), priority: URGENT
3. **Concert Trigger**: Automation Rule triggers Concert Workflow
4. **Concert → AAP**: HTTP Request block POSTs to AAP job template launch endpoint
5. **AAP Orchestration**: Fetch Lightwell artifact, update requirements.txt, commit to Gitea
6. **Gitea CI/CD**: Pipeline builds with PyYAML 6.0.2, runs tests, deploys application
7. **AAP Validation**: Verify dependency version, test application health, confirm CVE resolved
8. **Audit Trail**: Complete workflow history across Concert, AAP, Gitea

= Concert + AAP + Lightwell CVE Remediation Lab
:toc: auto

A hands-on workshop demonstrating enterprise-scale, event-driven CVE remediation using
Event-Driven Ansible to ingest CVE alerts, Automation Orchestrator to orchestrate the
response, IBM Concert to provide enterprise-wide SBOM inventory and dependency topology,
Red Hat Lightwell for remediated dependencies, and Gitea CI/CD for automated deployment.

== Workshop Modules

[cols="1,2,2"]
|===
| Module | Focus | Hands-on exercises

| *TRIAGE -- CVE Detection & Concert Inventory*
| Event-Driven Ansible receives CVE-2026-52891 alert (PyYAML deserialization) and triggers
Automation Orchestrator. Concert's pre-indexed SBOM inventory instantly identifies 12 affected applications
(including flask-api-app). Arena View topology shows deployment environments and downstream dependencies.
AO switch node routes to auto-remediation based on production deployment status.
| Trigger CVE webhook; observe EDA rulebook activation; review Concert SBOM inventory (enterprise-wide);
examine Concert Arena View topology; watch AO switch node decision.

| *ORCHESTRATE -- Automation Orchestrator Remediation*
| Automation Orchestrator orchestrates the remediation: fetch Lightwell artifact, update dependencies
in Gitea, monitor CI/CD pipeline, validate remediation, and update Concert status.
| Execute Automation Orchestrator workflow; observe Lightwell integration; monitor Gitea pipeline;
review job execution history; examine audit trail.

| *VALIDATE -- Audit Trail Review*
| Review complete audit trail: EDA webhook receipt, Automation Orchestrator execution history,
Concert API queries and status updates, Gitea commits and pipeline logs, application health checks.
| Review Automation Orchestrator execution history; examine Concert CVE dashboard (status: RESOLVED);
generate compliance report with complete audit trail.
|===

== Setup

The automated setup provisions infrastructure and configures Concert Workflow, AAP job
templates, and the vulnerable Flask application. Students will execute the remediation
workflow and observe the CVE lifecycle.

=== What the setup creates

* Flask application with PyYAML 5.4.1 (vulnerable to CVE-2026-52891)
* Gitea server with application repository and CI/CD pipeline
* EDA rulebook for CVE webhook ingestion
* Automation Orchestrator workflow with Concert inventory/topology query nodes
* AAP job templates for Concert SBOM queries, topology queries, and remediation
* Concert SBOM inventory pre-populated with application data

=== What attendees execute

* Trigger CVE alert via EDA webhook
* Observe EDA rulebook activation and Automation Orchestrator trigger
* Review Concert SBOM inventory results (12 affected apps from portfolio)
* Review Concert Arena View topology (deployments, dependencies)
* Monitor Automation Orchestrator workflow execution (decision logic, routing)
* Watch Gitea CI/CD pipeline build and deploy
* Review complete audit trail (EDA → AO → Concert → Gitea → App)

== Prerequisites

* OpenShift Virtualization cluster with RHDP provisioner
* AAP 2.7+ controller (shared or per-lab)
* IBM Concert instance (shared, cloud-hosted)
* Red Hat Lightwell access
* RHEL 9.x base image

== Lab Flow

1. **EDA Alert Ingestion**: CVE-2026-52891 alert received via webhook
2. **EDA Trigger**: EDA rulebook triggers Automation Orchestrator workflow
3. **Concert SBOM Inventory Query**: AO queries Concert's pre-indexed database → 12 affected apps (including flask-api-app)
4. **Concert Topology Query**: AO queries Arena View → production deployment, 1 downstream dependency
5. **AO Routing Decision**: Switch node evaluates (production deployment + CVSS 9.8 = auto-remediate)
6. **Lightwell Artifact**: AO job template fetches Lightwell-remediated PyYAML 6.0.2
7. **Gitea Update**: AO job template updates requirements.txt, commits, pushes to Gitea
8. **Gitea CI/CD**: Pipeline builds with PyYAML 6.0.2, runs tests, deploys application
9. **AO Validation**: Job template verifies dependency version, tests application health
10. **Concert Inventory Update**: AO job template updates Concert SBOM (pyyaml: 5.4.1 → 6.0.2)
11. **Audit Trail**: Complete workflow history across EDA, AO, Concert, Gitea, application
